# stale

**Point it at a folder of notes and it tells you which ones have gone out of
date with the things they point at — with the evidence that produced each
verdict.**

A pile of notes rots from the edges. The note is still there, still readable,
still confidently telling you to *see the setup doc* — and the setup doc was
renamed eight months ago. Markdown does not notice. The link renders, the
anchor renders, and the code block you pasted out of a source file renders
exactly as it did the day you pasted it, including the two lines that source
file no longer contains.

stale finds three kinds of rot and shows its working for every one:

| kind | what it catches |
|---|---|
| `link` | an internal link whose target file is not in the tree |
| `anchor` | a link to a heading the target no longer has |
| `quote` | a fenced block claiming to be copied from a source whose lines have since changed |

```bash
python stale.py corpus
```

```

notes/limits.md:41  link   header-split.md#why-...  case-only-match  no notes/header-split.md; notes/Header-Split.md differs only in case
notes/retry-budget.md:20  quote ../src/parse.py#L12-L20  content-drifted  src/parse.py line 19: source '...(backoff * (2 ** n))', note '...(backoff * (2 ** n))  # TODO'
------------------------------------------------------------------------------
30 notes, 136 references, 45 stale in 22 notes (base rate 73%)
25 distinct fixes would clear all 45
```

A quoted block declares where it came from, and that declaration is the thing
being checked:

~~~markdown
<!-- from: ../src/parse.py#L12-L20 -->
```python
def retry(fn, attempts=3, backoff=0.5):
    ...
```
~~~

## As a library

```python
from stale import read_tree, scan

rep = scan(read_tree("notes/"), case="strict", anchors="slug", quote="exact")

for f in rep.stale:
    print(f.note, f.line, f.reason, "|", f.evidence)

print("%d fixes clear %d findings" % (len(rep.causes()), len(rep.stale)))
```

## 🔴 The corpus is invented, and that is stated here rather than in a footnote

There is no public archive of one person's notes, and borrowing somebody
else's is both a privacy problem and a licensing one. So the 30 notes and 6
source files under `corpus/` were generated by `make_corpus.py` from the fixed
seed `20260083`, and re-running it reproduces the tree byte for byte.

What that costs: every point estimate below is a property of *this* tree and
would move on a real one. What transfers is the shape — that the three option
flags disagree with each other at all, and roughly how much, follows from how
markdown and filesystems work, not from the draw. The defects were not placed
to hit a number: the generator draws each reference from a distribution, and
the counts were measured afterwards by running the tool.

## 🔴 Four things it is opinionated about

**The case mode is a choice, and the default is the strict one.** NTFS and
APFS match filenames case-insensitively; ext4 does not. A link written as
`setup.md` against a file called `Setup.md` therefore works on the laptop it
was written on and 404s the moment the notes are published from Linux. stale
resolves against an index of the tree rather than against the filesystem, so
the answer is the same on every machine — **9 of the 95 link references in the
corpus (9.5%) resolve only case-insensitively**, across 9 notes and 7 target
files. A checker built on `os.path.exists` calls all nine of those fine on
Windows and all nine broken in CI, and never mentions that it changed its mind.

**There is no one anchor convention, so you pick one and stale tells you what
it cost.** GitHub lowercases a heading, *drops* punctuation rather than
replacing it, hyphenates spaces, and suffixes a repeat with `-1`. The
hand-rolled version everybody writes lowercases and hyphenates and stops
there. They are not close: over the corpus's **27 anchor references the two
conventions disagree on 11 — 40.7%** — and the disagreement goes both ways, 6
that only `slug` accepts and 5 that only `raw` accepts. `Rollout / rollback`
slugs to `rollout--rollback`, with two hyphens, because the slash is deleted
and both spaces survive.

**Whitespace normalisation is one line of code and it moves a third of the
quote verdicts.** Of the 14 quoted blocks, 7 differ from their source byte for
byte. **Two of those 7 — 28.6% — are identical once whitespace is
normalised**: re-indented when they were pasted, or carrying a trailing space.
Under `--quote exact` they are drift; under `--quote normalised` they are
clean. Same notes, same sources, one flag.

**The base rate is printed on every run, because it is the number that decides
whether anyone reads the report.** 45 findings sounds like a working detector
until you notice they fall in **22 of 30 notes — 73%**, and that across all
eight combinations of the three flags the rate never drops below 60%. A tool
that flags three quarters of the pile has not triaged anything. stale's answer
is `--causes`: the findings are not independent, and collapsing them onto the
thing you would actually repair turns **45 findings into 25 fixes, with the
top four clearing 18 of them**. One renamed file shows up once per note that
linked to it. Counting fixes instead of lines is the difference between a list
of symptoms and a list of jobs.

```bash
python stale.py corpus --causes
```

## Flags

```
--case     strict | insensitive     how a path is matched      (default strict)
--anchors  slug   | raw             how a heading is matched   (default slug)
--quote    exact  | normalised      how a block is compared    (default exact)
--causes                            group findings onto the fixes
--all                               show the healthy references too
--json
```

Exit code is `2` when anything is stale, `0` when nothing is, `1` when there
was nothing to read.

## Tests

```bash
python -m pytest test_stale.py -q      # 84 tests
```

They guard the four invariants worth guarding: a verdict never comes back
without the evidence that produced it; the answer does not depend on the
filesystem the checker happens to be running on; each flag moves the result in
a stated direction and nowhere else; and markdown is parsed rather than
grepped, so a `#` inside a code fence is not a heading.
